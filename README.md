# rhythmic-gymnastics-assistant

Веб-приложение для анализа видео упражнений художественной гимнастики и выдачи рекомендаций по коррекции техники: ловля двух булав после кувырка, прыжок с прогибом назад, равновесие на одной ноге, пируэт, переворот вперёд

## 📁 Структура проекта

- `index.html`, `style.css`, `script.js` — фронтенд (статический сайт)
- `live.html` — Live-режим: анализ с веб-камеры в браузере (MediaPipe Tasks JS, GPU), звуковая сигнализация, замер латентности
- `main.py` — бэкенд на FastAPI (загрузка видео, анализ позы через MediaPipe)
- `club_tracker.py` — трекинг булав (HSV-сегментация + опциональная ONNX-модель)
- `storage.py` — хранение отчётов тренировок (JSON + видео + кадры, автоочистка через 7 дней)
- `report_generator.py` — генерация PDF-карточки тренировки (reportlab)
- `train_club_detector.py` — обучение собственной модели детекции булав (YOLOv8)
- `test_main.py` — тесты (unittest) для бэкенда
- `requirements.txt` — зависимости Python
- `requirements-train.txt` — зависимости для обучения модели
- `uploads/temp/` — временная директория для загруженных видео
- `uploads/reports/<id>/` — отчёты: `meta.json`, видео, `frames/` (скриншоты ошибок, тепловая карта).
  Директория создаётся автоматически при сохранении первого отчёта (в репозитории её нет)
- `scripts/download_pose_model.py` — CLI-скрипт скачивания модели PoseLandmarker
  (`pose_landmarker_lite.task`) с фиксацией и проверкой SHA-256 (pin-файл
  `pose_landmarker_lite.task.sha256`). Запуск: `python scripts/download_pose_model.py`.
  Выполняется на этапе CI; при старте приложения скачивание не производится —
  только проверка целостности по pin-хешу

## 📊 Метрики анализа движений

Бэкенд вычисляет следующие метрики на основе позы человека (MediaPipe Pose):

| Метрика | Описание |
|---------|----------|
| `torso_tilt` | Угол наклона корпуса от вертикали (средний, макс., мин.) |
| `wrist_height` | Высота запястий при подбросе (средняя, макс., досягаемость, самая нижняя точка `lowest_y`); при наличии данных — досягаемость каждой руки отдельно (`left_reach_ratio`, `right_reach_ratio`) для выявления асимметричного подброса |
| `trajectory` | Траектория центра масс (путь, размах X/Y) |
| `motion` | Скорость и плавность движения (средняя/макс. скорость, плавность, рывки) |

### Признаки, специфичные для упражнений

Бэкенд дополнительно собирает признаки, которые осмысленны только для конкретных упражнений:

| Признак | Упражнение | Описание |
|---------|------------|----------|
| `knee_angle` | `balance` | Угол в коленном суставе (0–180°). Чем ближе к 180°, тем выпрямленнее опорная нога |
| `leg_opening` | `jump` | Угол раскрытия ног (шпагат) между векторами «таз → левая стопа» и «таз → правая стопа» |
| `hip_height` | `jump`, `risk-buhavy` | Нормализованная высота таза (верхняя точка — прыжок, нижняя — группировка в кувырке) |
| `torso_tilt_signed` | `rotation` | Наклон корпуса от вертикали со знаком (симметрия оси вращения) |
| `ankle_height` | `jump` | Средняя нормализованная высота стоп (оценка высоты отрыва) |
| `ankle_y` | `balance` | Высоты левой/правой лодыжки и их разница (определение опорной ноги: ниже стопа — опорная) |
| `arm_symmetry` | `rotation` | Асимметрия рук: модуль разницы высот запястий (0..1, 0 — идеально симметрично) |
| `rotation_turns` | `rotation` | Число витков в пируэте по углу поворота плечевой линии (3D world landmarks) |
| `wrist_height.lowest_y` | `walkover-front` | Самая низкая точка запястий за видео (0..1, y растёт вниз) — признак постановки рук на опору перед проходом |

## 🪄 Трекинг булав (полёт предметов)

MediaPipe Pose детектирует только скелет человека, поэтому параметры полёта булав
(высота броска, симметрия, одновременность, позиция ловли) отслеживаются отдельным
модулем `club_tracker.py`.

Два режима работы:

1. **HSV-сегментация (по умолчанию)** — булавы выделяются по яркой окраске
   (жёлтый/оранжевый/красный) в пространстве HSV, контуры превращаются в детекции.
2. **Кастомная ONNX-модель** — если файл `club_detector.onnx` лежит рядом с `main.py`,
   детекция выполняется моделью (приоритет), HSV используется как fallback.

Метрики полёта (`clubs` в ответе API):

| Поле | Описание |
|------|----------|
| `clubs_detected` | Число обнаруженных булав (0–2) |
| `throw_height` | Высота броска каждой булавы (нормализованная, 0 — верх кадра) |
| `symmetry` | Разница высот пиков левой/правой булавы (`height_diff`) |
| `simultaneity` | Разница кадров достижения верхней точки (`peak_frame_diff`, `simultaneous`) |
| `catch_position` | Координаты точки ловли (x, y) для каждой булавы |

### Обучение собственной модели

```bash
pip install -r requirements-train.txt

# Датасет в формате YOLO: dataset/{images,labels}/{train,val}
python train_club_detector.py --data dataset/data.yaml --epochs 50 --export-onnx
```

После обучения скопируйте `runs/detect/train/weights/best.onnx` в корень проекта
как `club_detector.onnx` — бэкенд подхватит его автоматически.

## 👥 Форматы анализа

Бэкенд поддерживает два формата (поле `format` в форме и в ответе):

| Формат | Описание |
|--------|----------|
| `individual` | **Основной формат.** Анализируется одна гимнастка — выбирается самый крупный скелет в кадре (обычно это передний план). Посторонние спортсменки в кадре не влияют на результат, если целевая гимнастка крупнее |
| `group` | Групповое упражнение: анализируются **5 гимнасток** (5 самых крупных скелетов). Для каждой гимнастки считаются свои метрики и рекомендации (`athletes` в ответе) |

### Как выбираются гимнастки

1. MediaPipe Pose возвращает **все** обнаруженные скелеты.
2. Скелеты сопоставляются между кадрами в треки (по близости центра) — `AthleteTrack`.
3. Выбираются целевые треки: `individual` — 1 самый крупный, `group` — 5 самых крупных.

### Ответ для группового формата

```json
{
  "format": "group",
  "athletes": [
    { "index": 0, "movement": { ... }, "feedback": { ... } },
    { "index": 1, "movement": { ... }, "feedback": { ... } }
  ],
  "clubs": {
    "format": "group",
    "athletes": [ { "clubs_detected": 2, ... }, ... ],
    "clubs_detected_total": 10
  }
}
```

> ⚠️ Для группового формата булавы связываются с гимнастками по близости к запястьям.
> Если гимнастки стоят близко друг к другу, возможны ошибки привязки.

### Командная обратная связь (групповой формат)

Помимо индивидуальных оценок, для группового формата формируется блок `team_feedback` —
общие для команды замечания, построенные на сопоставлении событий гимнасток по кадрам:

| Правило | Условие | Пример сообщения |
|---------|---------|------------------|
| Рассинхрон старта движения | Разброс кадров первого значимого движения центра масс > 0.3 с | «Рассинхрон старта движения 0.4 с: гимнастка №1 начинает раньше остальных, гимнастка №5 — позже» |
| Потеря ритма после падения булавы | Булава упала у одной гимнастки, остальные остановились (пауза ≥ 2 кадров) | «Команда теряет ритм после падения булавы у гимнастки №3: 4 из 4 остальных остановились» |

Критерий падения булавы (`dropped` в результате `analyze_club_flight`) — эвристический:
траектория заканчивается у пола (последний y ≥ 0.85) и после пика не поднимается обратно.
Командный блок выводится на фронтенде («🤝 Командные замечания») и в PDF-карточке,
но не влияет на индивидуальные оценки — чтобы сохранялась сравнимость отчётов.

## 🎥 Live-режим (реальное время)

Страница `live.html` — анализ с веб-камеры **прямо в браузере**, без отправки
видео на сервер:

- **Задержка кадра < 100 мс**: MediaPipe PoseLandmarker в режиме `LIVE_STREAM`
  (GPU-делегат), замер `avg / p95` выводится на экран с индикацией цели;
- **Звуковая сигнализация**: Web Audio API (beep) при нарушении порога техники,
  с кулдауном 3 с (настраивается галочками);
- **Правила**: JS-порт подмножества `THRESHOLDS` из `main.py`
  (равновесие: раскачивание, наклон, опорная нога; пируэт: ось, симметрия рук;
  прыжок: прогиб; переворот вперёд: вертикальность прохода, постановка рук на пол) —
  пороги синхронизированы вручную;
- **Ограничения live-режима**: трекинг булав, групповой формат из 5 гимнасток
  и PDF-отчёты доступны только в пакетном режиме (загрузка файла).

## 📄 Экспорт отчёта (PDF-карточка тренировки)

После успешного анализа появляется кнопка **«💾 Сохранить отчёт (PDF)»** — сервер
формирует карточку тренировки, которую можно распечатать или отправить родителям.

PDF-карточка содержит:

- миниатюру видео и оценку техники (0–100);
- скриншоты моментов ошибок с обводкой скелета;
- кликабельные таймкоды — ссылка открывает веб-плеер (`/video-player/<id>?t=<сек>`)
  на моменте ошибки в исходном видео;
- текст каждой ошибки, рекомендацию и предлагаемое корректирующее упражнение
  (словарь `SUGGESTED_DRILLS` в `main.py` — можно дополнять);
- **динамику**: сравнение с предыдущей тренировкой по тому же элементу
  («Угол разгибания вырос на 5° по сравнению с 05.10»);
- **тепловую карту перемещений** для группового формата: где 5 гимнасток
  сбиваются в кучу (метрики `peak_density`, `overlap_ratio`).

Эндпоинты:

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/reports/{id}/pdf` | PDF-карточка тренировки |
| GET | `/reports/{id}/video` | Исходное видео (для плеера) |
| GET | `/reports/{id}/frames/{name}` | PNG-кадры (ошибки, тепловая карта) |
| GET | `/video-player/{id}?t=12.5` | Веб-плеер с переходом к таймкоду |

> Отчёты (включая видео) хранятся в `uploads/reports/` и автоматически удаляются
> через 7 дней (константа `RETENTION_DAYS` в `storage.py`).

## 🎯 Оценка техники и рекомендации

Помимо метрик, бэкенд формирует блок `feedback` — ядро продукта: детекцию ошибок
и рекомендации по коррекции техники для выбранного упражнения.

Ответ включает:

| Поле | Описание |
|------|----------|
| `overall_score` | Общая оценка техники (0–100). Старт со 100, штраф −25 за критичную ошибку, −10 за замечание |
| `errors` | Список найденных ошибок с severity (`critical` / `warning`) и описанием |
| `recommendations` | Конкретные советы по исправлению каждой ошибки |
| `summary` | Итоговое резюме выполнения |

Правила проверки заданы в словаре `THRESHOLDS` в `main.py`:

| Упражнение | Что проверяется |
|------------|-----------------|
| `risk-buhavy` | Глубина кувырка (макс. наклон корпуса), группировка (низкий уровень таза), высота подброса (в т.ч. по каждой руке отдельно — асимметричный подброс), параметры полёта булав (высота броска, симметрия, одновременность, позиция ловли), жёсткость ловли |
| `jump` | Высота прыжка (размах Y центра масс), глубина прогиба назад, раскрытие ног (шпагат), вертикальный отрыв (высота таза), высота отрыва стоп, мягкость приземления |
| `balance` | Раскачивание (размах X центра масс), наклон корпуса, выпрямленность опорной ноги (опорная — та, чья стопа ниже, определяется по высоте лодыжек) |
| `rotation` | Завал оси вращения (средний наклон), смещение центра масс, систематический завал в одну сторону, число витков (3D), симметрия рук, неравномерность вращения |
| `walkover-front` | Проход через стойку на руках (макс. наклон корпуса ≥ 150°), раскрытие ног (шпагат ≥ 150°), прямые ноги (мин. угол в колене ≥ 150°), постановка рук на опору (`lowest_y` ≥ 0.70), плавность выхода (рывки ≤ 15) |

> Для `walkover-front` блок `recommendations` всегда включает подводящие упражнения
> (колесо через одну руку, перекат через стойку у стены, мостик и растяжка плеч) —
> независимо от найденных ошибок, включая идеальное выполнение.

> ⚠️ Пороговые значения — эвристические и уточняются по мере накопления данных.

## 📏 Валидация метрик и ограничения

Чтобы цели формулировались проверяемо, важно понимать, **что именно измеряет система**:

| Заявленная цель | Что измеряется сейчас | Что нужно для строгой проверки |
|-----------------|----------------------|-------------------------------|
| «Точность распознавания ключевых точек ≥ 90%» | `pose_presence` — доля кадров, где поза **обнаружена** (detection rate, не точность координат) | Ground truth: экспертная разметка выборки кадров + расчёт PCK@0.2 / PCKh@0.5. Скрипт не входит в текущую поставку |
| «Снижение критических ошибок на 30%» | `GET /stats/{exercise}` — тренд числа critical-ошибок **по данным детектора** (среднее в первых k vs последних k сессиях; порог `k=3` по умолчанию, тренд считается от 2·k сессий) | Валидация правил детектора против экспертизы тренера (confusion matrix) и когортный pre/post-протокол (несколько спортсменок). До этого тренд — измеримый прокси, а не доказательство |

Как пользоваться `/stats`:

```bash
curl "http://127.0.0.1:8000/stats/balance?format=individual&k=3"
```

Ответ содержит `trend`: `{sessions, window_k, early_avg_critical, late_avg_critical,
delta_pct}` (delta_pct < 0 — срабатываний детектора стало меньше). Тот же тренд
выводится в PDF-карточке (блок «Динамика», от 4 тренировок).

Пороги правил (`THRESHOLDS`) — эвристические и не проходили валидацию против
экспертной оценки техники; корректируйте значения по мере накопления данных.
